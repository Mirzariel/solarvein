### Motion observations (from code only; stills cannot show motion)

- 3D effects use exponential damping `SCENE_RATE = 3.3` (about 0.9 s to settle) for sun, rain, mood, arrow strength: consistent with the 700-1200 ms weather target.
- BUT `setMode` loads the preset into the store instantly (`state/store.ts`), so the simulation jumps and only the visuals damp toward the new targets; intermediate frames are not real computed states (brief: interpolate inputs, re-run `simulate()`). HeatArrows cross-fades through zero when direction flips (good), yet this is a visual fade of a discrete flip, not a physics-driven crossing of Q=0. UI numerals use `useAnimatedNumber` (500 ms) so metrics will count while 3D moves at a different rate: potential mismatch.
- Camera: exponential approach with rate 7/s (about 0.43 s to 95 %), faster than the 600-1000 ms brief; OrbitControls damping 0.08 (inertial, good); wheel zoom is also goal-based (good).
- UI: only `transition-colors 200 ms ease-standard` (not `cubic-bezier(.22,1,.36,1)`); SegmentedControl has no thumb travel; no panel reveal, no section entrance, no chart enter animation; `prefers-reduced-motion` is handled (global CSS + effects static), good.
- Render loop: `frameloop` gated to in view, `dpr [1,1.75]` (good), Rain 600 instanced + 150 ripples with additive blending (overdraw risk on weak GPUs; not measured).

2. **Cut to four sections + footer with ~1,200 visible words, no default cards** (D-05, D-13, D-14, D-15, D-23, D-24): rhythm, scannability, and no repeated claims.
